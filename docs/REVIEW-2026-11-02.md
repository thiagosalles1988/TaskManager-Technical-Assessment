## Findings

### M1 — MEDIUM: error content negotiation changes client errors into 500s

**Location:** `src/TaskManager.Api/ApiExceptionHandler.cs:28`; related unconditional documentation claim in `docs/ARCHITECTURE.md` under HTTP and error boundaries.

**Issue:** `IProblemDetailsService.WriteAsync` throws when no writer accepts the request's Accept header. The intended 400/401/404/409 handling can itself fail. Reproduction: POST `/api/auth/register`, body `{"email":"bad","password":"short"}`. `Accept: application/json` returns 400 ValidationProblemDetails. `Accept: text/plain`, `text/html` or `application/xml` returns 500. The independent reviewer confirmed empty 500 responses in Testing; the main reviewer confirmed that Development additionally exposes the original stack trace through the developer exception page. The documented statement that no environment receives stack traces is therefore false for this path. No Production stack disclosure was demonstrated.

**Impact:** breaks consistent error/HTTP semantics, hides useful validation feedback, adds server-error noise, and leaks internal paths/stack information in Development. Angular's usual JSON Accept header does not trigger it. This is not a demonstrated authentication bypass or production data leak.

**Correction:** use `TryWriteAsync` with a deliberate fallback preserving the intended status and safe body, or return a documented 406 negotiation result. Ensure the handler cannot fall through to the development exception page. Add regression cases for validation, wrong credentials and not-found with incompatible Accept headers in both Development and Production/Testing; correct the documentation claim.

### M2 — MEDIUM: offsetless due dates depend on the server timezone

**Location:** `src/TaskManager.Application/Contracts.cs:5`, bound by default JSON options in `src/TaskManager.Api/Program.cs:15`.

**Issue:** a DateTimeOffset DTO does not enforce an explicit offset. Real authenticated POSTs to the isolated SQL-backed API both returned 201:

| Input dueDateUtc       | Persisted/returned instant on this host |
| ---------------------- | --------------------------------------- |
| `2026-11-04T15:00:00`  | `2026-11-04T18:00:00+00:00`             |
| `2026-11-04T15:00:00Z` | `2026-11-04T15:00:00+00:00`             |

**Impact:** a caller omitting the timezone gets a host-dependent instant despite the DueDateUtc name and UTC contract. A host timezone change can shift the meaning of the same request. The Angular client sends explicit UTC, so its normal creation flow passed.

**Correction:** define and enforce the wire policy: require `Z` or an explicit ISO offset and return 400 otherwise, or explicitly define offsetless input as UTC in a custom converter. Preserve support for null and legitimate overdue dates. Test the policy and offset normalization rather than relying on the host timezone.

### M3 — MEDIUM: development toolchain retains known vulnerable dependencies

**Location:** `taskmanager-web/package-lock.json:5564` (`glob` 13.0.6), `taskmanager-web/package-lock.json:6385` (`minimatch` 10.2.6); dependency entry `taskmanager-web/package.json:26`.

**Issue:** a fresh full `npm audit --json` exits 1 with 16 moderately affected development dependencies, including inherited exposure through the Angular CLI tree. Root advisories include [minimatch pattern-amplification denial of service](https://github.com/advisories/GHSA-g3hv-75wg-m249) and [glob cancellation bypass](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4). These are affected-package counts, not 16 independently demonstrated application exploits. Production-only npm audit exits 0 with no findings; no browser-bundle exploit was demonstrated.

**Impact:** CPU/memory/filesystem availability risks in tooling that processes attacker-influenced patterns or trees, particularly shared builds and untrusted projects. Documentation acknowledges the tooling risk but does not remediate it.

**Correction:** upgrade a compatible Angular CLI/build/framework dependency set to one resolving patched versions; regenerate/review the lockfile and rerun build/unit/browser tests and full audit. The advisories identify minimatch 11.0.1 and glob 14.0.2 as patched floors. Do not blindly force an incompatible CLI major or assume a transitive override preserves APIs.

### L1 — LOW: repository tests overstate independent SQL invariant coverage

**Location:** `tests/TaskManager.IntegrationTests/RepositoryTests.cs:48` and `:63`.

**Issue:** the invalid-data insert supplies both blank title and status 7 and expects any SqlException. Removing either CHECK constraint alone leaves that test green. The foreign-owner UPDATE test passes an entity whose UserId differs from the caller, causing the repository's pre-SQL guard to return false; it does not isolate the UPDATE statement's ownership predicate. Both protections exist in actual source. Additional review probes independently verified that invalid-status-only and blank-title-only inserts hit their respective CHECK constraints with SQL error 547.

**Impact:** regression tests may pass after an individual SQL defense is accidentally removed; passing tests do not establish the full claim their names suggest.

**Correction:** split title/status cases, assert the intended SQL constraint failure, and test a forged entity using a victim task ID but attacker UserId/caller so the UPDATE reaches SQL and must affect zero rows. Retain real SQL and HTTP ownership tests.

### L2 — LOW: missing SQL configuration skips all API-pipeline security tests

**Location:** `tests/TaskManager.IntegrationTests/ApiTests.cs:29`, `tests/TaskManager.IntegrationTests/TestDatabase.cs:25`.

**Issue:** the shared API fixture requires a database before any test runs, including public access, missing/invalid JWT and injected generic-error cases that need no persistence. Without the environment variable, those HTTP cases are all ignored. The skip is honest and documented; SQL was configured and none were skipped during this review.

**Impact:** a green SQL-less developer/CI run loses HTTP authentication, serialization and error-pipeline regression coverage.

**Correction:** retain the SQL end-to-end fixture, add a separate pipeline fixture using repository substitutes only for database-independent HTTP cases, and make the required SQL CI lane fail rather than silently skip when its configuration is missing.

### L3 — LOW: editing a task can silently truncate the due instant

**Location:** `taskmanager-web/src/app/tasks/task-form.ts:43`, consumed by `taskmanager-web/src/app/tasks/task-editor.component.ts:116`.

**Issue:** converting the original instant to datetime-local slices it to minute precision; save reconstructs a new instant even when only the title changed. An API-created due date ending in `:45` seconds is therefore rewritten ending in `:00`. This is established by source inspection and is already documented as a limitation; it was not represented as a new executed browser scenario.

**Impact:** unrelated edits can change a valid stored due date. Usually low practical impact for this small task manager, but it is a lossy round trip.

**Correction:** preserve the original UTC instant when the due-date control is unchanged, or carry supported seconds/fractions through the control and contract. Add a round-trip test that edits only the title of a task with nonzero seconds.

### L4 — LOW: non-flags task statuses accept combined enum names

**Location:** `src/TaskManager.Api/Program.cs:16`.

**Issue:** the built-in enum converter accepts `"Todo, InProgress"` and the real API returned 201 with InProgress. Domain validation sees a defined resulting numeric value, so it cannot distinguish this undeclared wire representation. Integer JSON inputs are correctly refused by existing tests.

**Impact:** the wire grammar is broader than the stated three status strings. No unsupported stored state or privilege escalation was demonstrated.

**Correction:** use a strict status converter/request mapping accepting exactly the supported string names according to a documented casing policy; test combined and numeric-string representations. Do not mislabel the current behavior as a database status-constraint bypass.
